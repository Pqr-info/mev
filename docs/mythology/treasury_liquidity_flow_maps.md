### *Extended Chronicle — Volume XXIII*  
### *Cartography of Stability, Volatility, Solvency, and Temporal Pressure in the Sovereign‑27 Mesh*

---

## **1. Purpose of Liquidity Flow Mapping**

The Treasury Liquidity Flow Maps define:

- how **STBL** (stability) moves through the mesh  
- how **VFUT** (volatility) propagates  
- how **PNIR** (temporal interest rate pressure) rises and falls  
- how **solvency** is maintained or lost  
- how **liquidity cycles** synchronize with the Sovereign Clock  
- how **economic signals** travel between Zeta, Ted, Max, and future nodes  

These maps are the **vascular system** of the civilization.

---

# **2. The Four Liquidity Domains**

Treasury liquidity flows through four constitutional domains:

1. **Stability Domain (STBL)**  
2. **Volatility Domain (VFUT)**  
3. **Pressure Domain (PNIR)**  
4. **Solvency Domain (S)**  

Each domain has its own flow map.

---

# **3. Stability Flow Map (STBL)**

### **3.1 STBL Origin**
STBL is minted by the Treasury when:

- drift is low  
- volatility is low  
- SRRK consistency is high  
- routing is deterministic  

### **3.2 STBL Flow Path**

```
Treasury → Zeta → Ted → Max → Future Nodes
```

### **3.3 STBL Propagation Rules**
- flows only downstream  
- cannot move upstream  
- cannot bypass identity hierarchy  
- must follow clock propagation timing  

### **3.4 STBL Effects**
- lowers volatility  
- increases solvency  
- stabilizes routing  
- strengthens identity  

---

# **4. Volatility Flow Map (VFUT)**

### **4.1 VFUT Origin**
VFUT is generated when:

- drift rises  
- jitter spikes  
- packet disorder occurs  
- SRRK conflicts appear  
- thermal instability increases  

### **4.2 VFUT Flow Path**

```
Node → Treasury → Circuit Breaker → Mesh Shell
```

### **4.3 VFUT Propagation Rules**
- flows upstream  
- cannot be blocked  
- must be reported  
- triggers penalties  

### **4.4 VFUT Effects**
- increases PNIR  
- reduces solvency  
- triggers burn events  
- destabilizes routing  

---

# **5. Pressure Flow Map (PNIR)**

### **5.1 PNIR Origin**
PNIR rises when:

- volatility increases  
- solvency decreases  
- mesh instability grows  
- arbitration conflicts escalate  

### **5.2 PNIR Flow Path**

```
Treasury → All Nodes (simultaneously)
```

### **5.3 PNIR Propagation Rules**
- flows omnidirectionally  
- affects all tiers equally  
- synchronized to the Sovereign Clock  
- cannot be delayed  

### **5.4 PNIR Effects**
- increases drift sensitivity  
- accelerates VFUT burn  
- tightens solvency thresholds  
- amplifies volatility penalties  

---

# **6. Solvency Flow Map (S)**

### **6.1 Solvency Formula**

\[
S = STBL_{balance} - VFUT_{liability}
\]

### **6.2 Solvency States**
- **Solvent:** S ≥ 0  
- **At Risk:** S < 0  
- **Default:** S < −θ  

### **6.3 Solvency Flow Path**

```
Treasury ↔ Node
```

Solvency is a **bidirectional** flow:

- STBL increases solvency  
- VFUT decreases solvency  

### **6.4 Solvency Effects**
- determines economic health  
- affects identity stability  
- influences routing priority  
- impacts arbitration outcomes
